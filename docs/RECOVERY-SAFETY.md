# 冲突解决与恢复流程加固

## 冲突保存

冲突加载先记录原始 Git 索引字节 SHA-256，再解码各版本及工作区文件，最后复核索引。工作区文本快照携带该索引摘要，仓库刷新保留草稿对应的旧快照。

保存操作必须先成功创建恢复点；安全写入在写入前及替换前同时检查工作区文件和原始索引摘要，暂存前再次检查索引。任何已检测到的竞争都中止后续步骤。

文件已写入而暂存失败（包括此阶段取消）时，返回 `WorktreeSaved=true`、`ExecutionStage=stage-failed`、恢复点 ID，以及“文件已保存、暂存失败”。界面保留冲突草稿，不自动重写文件。核对工作区内容后可通过文件树暂存入口或 Git 暂存；不要把这次结果当成文件完全未保存。日志失败也不会把已完成的写入改报成全部失败。

## 新归档与创建保护

新归档清单版本为 2；清单逐项记录文件是否存在、长度、SHA-256，并包含原始索引、HEAD 与恢复引用信息。不存在的文件也有明确记录。

备份覆盖受影响路径、工作区变化及当前跟踪文件；目录展开为全部普通文件，不按文件大小跳过。文件读取前、复制后及整批结束时复核字节摘要、长度、时间和属性，最终重新核对 HEAD 与路径集合。新 ZIP 关闭并刷新到磁盘后，还会重新读取所有条目检验 CRC、长度和 SHA-256。验证完成后才发布归档与恢复引用；备份失败时禁止继续破坏性操作。

保留 50 个恢复点、2 GiB 总归档配额和普通恢复点 30 天保留期。创建前按完整输入长度、压缩开销及清单预留空间，并检查磁盘可用空间；复制数据与压缩流写入均有限额。单份完整备份或解压内容超过 2 GiB 时拒绝执行，不牺牲备份完整性来适配配额。恢复前安全点会被固定保留，同时仍占用数量和体积配额；固定安全点导致额度不足时停止新建，需在恢复中心明确删除不再需要的安全点。

## 恢复执行顺序

1. 校验清单身份与版本、路径边界、重复或多余条目和文件集合。
2. 把全部 ZIP 内容解压到恢复目录下的独立临时区。所有格式均校验解压长度及 CRC；版本 2 另外校验 SHA-256。旧清单没有版本/摘要字段时按版本 1 读取，但不跳过任何条目的解压验证。
3. 校验归档索引和当前索引：Git 索引头、版本、末尾校验值、索引解析及文件对象存在性。验证基准提交、对应恢复引用、仓库操作状态、目标路径和占用情况。发现越界、`.git` 写入、符号链接、子模块或文件/目录类型冲突时，在修改仓库前停止。
4. 创建并固定恢复前安全点。安全点失败则停止；再次核验当前文件和 HEAD，避免把准备期间发生的变化覆盖掉。
5. 持久化执行记录后，依次进行 `checkout`、`worktree`、`index`、`validation`。工作区文件先写同目录临时文件、落盘并复核目标后替换；索引使用独占创建的 `index.lock`，失败时不删除其他进程的锁。
6. 校验实际工作区字节、索引字节及 HEAD，全部完成才报告成功。

执行记录位于恢复目录的 `restore-*.json`，记录源恢复点 ID、恢复前安全点 ID、执行阶段、是否可能已修改仓库及错误。每个修改阶段开始前刷新记录到磁盘。中断时保留最后持久化的阶段；捕获到失败时补记失败阶段。不自动执行二次强制恢复。若日志更新本身遇到磁盘故障，返回该错误并保留此前的记录和固定安全点。界面刷新不会覆盖这次恢复结果的阶段及安全点提示。

损坏或无法解析的归档不会因为引用清理而丢失与其文件名对应的恢复引用。明确删除恢复点仍会执行既有的归档与引用清理流程。

## 加密草稿

解密、解析或身份校验失败时，把原始加密文件原样移入 `Drafts/quarantine`，使用唯一文件名；不立即删除。正常草稿删除、保存和过期清理均不触及隔离目录。隔离失败时原文件仍保留并报告错误。

新草稿携带原始字节摘要、编码和 BOM 信息。恢复草稿确认后重新严格打开源文件并核对摘要；旧草稿缺少新元数据时也必须通过该复核。源文件在确认期间改变或变为不可安全解码时，不恢复到可写编辑器，原加密草稿保留。新草稿原始摘要与当前源文件不匹配时，保留旧摘要阻止后续静默覆盖。

## 保证边界

多文件恢复、分支切换、文件保存与暂存不是跨资源事务。强制终止或中途错误可能留下部分已恢复的状态，此时应依据执行阶段、安全点和当前仓库实际状态人工决定下一步。安全点包含工作区、索引及基准提交，不用于重建未结束 Git 操作的全部控制文件；执行恢复前仍须先结束当前 Git 操作。

同一进程使用仓库锁及恢复锁；索引写入采用 Git 锁文件协议。外部程序仍可能在最终检查与替换之间竞争，不能承诺完全消除该窗口。检测到的竞争直接中止，保留恢复依据。
