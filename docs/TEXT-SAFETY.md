# 统一文本识别与安全保存

普通文件编辑、历史文本查看、冲突版本解码共享 `TextFileStorage`；普通编辑与冲突结果写入共享保存实现。

- 按 UTF-8、UTF-16 LE/BE BOM 选择严格解码器，无 BOM 仅尝试严格 UTF-8。解码失败或含二进制控制字符时不展示替换字符，禁止文本保存，可使用现有外部打开入口。不会猜测 GBK，也未增加编码选择器。
- `TextDocument` 保存编码名、BOM 标记、换行序列、混合换行标记、末尾换行标记及原始字节 SHA-256。混合 CRLF/LF/CR、只读和超过 5 MiB 的文件不可编辑。
- 未改变文本的保存只校验原始字节，不重写目标；编辑后保留原 BOM 和编码，将编辑器换行转换为原文件的单一换行类型，不自动追加末尾换行。无换行文件新增换行采用 LF。无效代理字符不能编码写出。
- 保存首先检查工作区路径、只读状态和原始字节摘要。使用同目录唯一临时文件、CreateNew、严格编码字节写入、FlushAsync 和 Flush(true)，然后再次检查路径、文件状态及摘要，最后通过 File.Replace 替换已有目标。没有删除原文件后重建的回退路径。通常失败时清理临时文件；Windows 1176/1177 部分替换失败例外，会保留可能用于恢复的临时副本并显示路径。不会清除普通编辑草稿或冲突结果。
- 外部修改不再提供强制覆盖。可保留草稿，或明确选择重新载入磁盘内容。冲突刷新保留编辑草稿对应的原始快照，不能通过刷新绕过摘要校验。未取得原始快照的冲突文本写入会被拒绝；缺失的工作区文件需先通过外部工具处理。

## 保证边界

这是单文件的乐观并发保护，不是跨多个文件的事务；冲突文件写入与 Git 暂存也不是同一个事务。如果写入成功但暂存失败，工作区文件可能已经保存，冲突草稿仍保留。刷新到磁盘和同目录替换减少部分写入的风险，但不保证断电时所有文件系统行为。

两次校验不能彻底消除不受控外部程序在最终检查之后、替换之前写入的竞争，也不能识别所有“更改后恢复为相同字节”的操作。检测到的摘要或保存期间目标状态变化直接中止；不承诺对外部写入提供排他锁。临时文件清理若被权限或外部占用阻止，保留原始保存异常及 HResult，在异常 Data 中附带 TemporaryCleanupError、RetainedTemporaryPath；不能保证该异常条件下没有残留。不会为重试修改文件权限、强制解锁或关闭其他程序。

## 验证

`TextFileStorageTests` 覆盖 UTF-8 有/无 BOM、UTF-16 大小端、空文件、CRLF/LF/CR、末尾换行、有编辑及无编辑字节比对、无效 UTF-8/UTF-16、GBK 字节、混合换行、只读状态、仅 BOM 外部修改、无效编辑器代理字符，以及注入的部分写入/替换失败、写入期间外部修改/删除/状态变化/取消。

`GitRepositoryServiceTests` 使用真实 Git 合并验证四种编码的冲突解码、原始快照校验、BOM 保留和成功暂存；`RepositorySwitchingTests` 验证普通草稿及冲突刷新后的草稿与快照保留。

后续加固：冲突保存还会核对原始 Git 索引，并在写入前创建必需恢复点；部分完成状态及恢复流程详见 [恢复安全说明](RECOVERY-SAFETY.md)。

本版包含部分替换失败保留临时副本、清理异常不掩盖原始异常的修复；相关回归已纳入本版全量测试。
